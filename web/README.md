# เว็บไซต์ DA Training Academy (Firebase)

- **ที่อยู่เว็บ:** https://smilegallerytraining.web.app
- **โปรเจกต์ Firebase:** `smilegallerytraining` บนแพ็กเกจ Spark ซึ่งฟรีและไม่ต้องผูกบัตร
- **คอนโซล:** https://console.firebase.google.com/project/smilegallerytraining/overview
- เว็บนี้ใช้หน้าและเนื้อหาชุดเดียวกับ Artifact บน claude.ai (`index.html` และ `course.js` ฯลฯ) แต่มีระบบเข้าสู่ระบบ ลงทะเบียน การอนุมัติโดย HR และการจัดการผู้ใช้ของตัวเอง (`web/auth.js`) ส่วน Artifact เดิมยังใช้งานได้ตามปกติ

## ตั้งค่าครั้งแรกใน Firebase Console (ทำครั้งเดียว)

1. ไปที่ **Authentication → Get started → Sign-in method**
   - **Google:** กด Enable แล้วเลือกอีเมลสำหรับติดต่อของโปรเจกต์
   - **Email/Password:** กด Enable แต่ไม่ต้องเปิด Email link
   - เปิดทั้งสองวิธีไว้แล้วเมื่อ 7 พ.ย. 2569
   - **ไม่ต้องเปิดวิธีอื่น** (Facebook, เบอร์โทร, Anonymous ฯลฯ) เว็บนี้รับเฉพาะ Google กับอีเมล/รหัสผ่าน ถ้าเผลอเปิดไว้ หน้าเว็บจะออกจากระบบให้ทันที และ `firestore.rules` ก็ไม่ให้บัญชีแบบอื่นอ่านหรือเขียนข้อมูล
2. ไปที่ **Authentication → Settings → Authorized domains**
   - `smilegallerytraining.web.app`, `smilegallerytraining.firebaseapp.com` และ `localhost` มีอยู่แล้ว
   - เพิ่มโดเมนเฉพาะตอนจะใช้โดเมนของคลินิกเอง
3. ฐานข้อมูล Firestore `(default)` และกฎความปลอดภัยสร้างไว้แล้วตอน deploy ครั้งแรก

## ผู้ดูแลระบบคนแรก

- อีเมลที่อยู่ใน `admins` ของ `web/site.json` เป็นผู้ดูแลระบบ
- **วิธีที่ง่ายที่สุด (Google):**
  1. เปิดเว็บ กด "เข้าสู่ระบบด้วย Google" แล้วเลือกบัญชี Gmail ของผู้ดูแลระบบ
  2. กรอกชื่อและสาขา (รหัสพนักงานเว้นว่างได้) แล้วส่งข้อมูล ระบบจะให้สิทธิ์ผู้ดูแลทันที เพราะ Google ยืนยันอีเมลให้แล้ว
- **ถ้าใช้อีเมลและรหัสผ่าน:**
  1. กด "สมัครใหม่" ใส่อีเมลผู้ดูแลระบบและตั้งรหัสผ่าน
  2. กรอกชื่อและสาขา แล้วส่งข้อมูล
  3. ที่หน้ารออนุมัติ กด "ส่งลิงก์ยืนยันอีเมล" แล้วเปิดลิงก์ในกล่องจดหมายของอีเมลนั้น
  4. กลับมากด "ยืนยันแล้ว" ระบบจะให้สิทธิ์ผู้ดูแลทันที
- ถ้าลืมรหัสผ่าน กด "ลืมรหัสผ่าน?" ระบบจะส่งลิงก์ตั้งรหัสใหม่ไปที่อีเมลนั้น (บัญชีที่สมัครด้วย Google ไม่มีรหัสผ่าน ให้กดปุ่ม Google ทุกครั้ง)
- พนักงานใหม่ลงทะเบียนเองได้ สถานะจะเป็น "รออนุมัติ" จนกว่าผู้ดูแลหรือ HR จะอนุมัติที่หน้า **สำหรับ HR → จัดการผู้ใช้**
- มีแต่ผู้ดูแลระบบที่ให้สิทธิ์ "HR / หัวหน้า" กับคนอื่นได้ ส่วน HR จัดการได้เฉพาะบัญชีผู้เรียน

## แก้เนื้อหาแล้วขึ้นเว็บใหม่

1. แก้เนื้อหาที่ `course.js` (ดูรูปแบบได้ที่ comment บนสุดของไฟล์)
2. ทดสอบในเครื่องด้วย Firebase จำลอง ซึ่งไม่แตะข้อมูลจริง (บัญชีตัวอย่างใช้รหัสผ่าน `test1234`):
   ```bash
   python scripts/build_web.py --fake --serve
   ```
   - เปิด http://127.0.0.1:8766/?reset=1&as=hr
   - เปลี่ยน `as=` ได้เป็น `admin`, `learner`, `pending` หรือ `new`
   - `as=google` คือบัญชี Google ใหม่ที่ยังไม่ลงทะเบียน (ปุ่ม Google ในเว็บจำลองเปิดหน้าต่างเลือกบัญชีจำลอง ไม่ใช่ Google จริง)
3. สร้างไฟล์จริงแล้วขึ้นเว็บ:
   ```bash
   python scripts/build_web.py
   cd dist-web
   firebase deploy
   ```
   - ถ้าแก้แค่เนื้อหา ใช้ `firebase deploy --only hosting`
   - ถ้าแก้ `web/firestore.rules` หรือรายชื่อ `admins` ใช้ `firebase deploy` เต็มคำสั่ง
4. ถ้าอยากให้ Artifact บน claude.ai ตรงกับเว็บด้วย ต้อง publish Artifact ใหม่อีกครั้ง (ดู `CLAUDE.md`)

`dist-web/` และ `.preview-web/` เป็นไฟล์ที่สร้างขึ้นใหม่ทุกครั้ง ไม่ต้องแก้และไม่ขึ้น git

## `web/site.json`

ไฟล์นี้ไม่ขึ้น git ถ้าตั้งค่าบนเครื่องใหม่ ให้คัดลอกจาก `site.example.json` แล้วกรอก 3 ส่วน:

- **`firebase`:** ค่า web config จาก Console → Project settings → Your apps
- **`admins`:** อีเมลผู้ดูแลระบบ ต้องสะกดให้ตรงทุกตัวอักษร
- **`branches`:** รายชื่อสาขา ถ้าเว้นว่าง ช่องสาขาจะเป็นช่องพิมพ์อิสระ

ต้องใช้ Firebase CLI (`npm install -g firebase-tools`) และ `firebase login` ด้วยบัญชีที่เป็นเจ้าของโปรเจกต์

## วิดีโอบทเรียน (YouTube)

- อัปโหลดวิดีโอลงช่อง YouTube ของคลินิกแบบ **Unlisted (ไม่เป็นสาธารณะ)** แล้วให้ HR วางลิงก์ในหน้าบทเรียน
- ลิงก์จะเก็บไว้ที่ Firestore `media/videos` และเว็บจะฝังวิดีโอให้
- Unlisted **ไม่ใช่ความลับ** ใครได้ลิงก์ก็ดูได้ จึงห้ามมีหน้าคนไข้หรือข้อมูลส่วนตัวในวิดีโอ
- วิดีโอที่ยาวเกิน 15 นาที ต้องยืนยันช่อง YouTube ด้วยเบอร์โทรก่อน

## ผู้ใช้

- **ลำดับปกติ:** เข้าด้วย Google หรือสมัครด้วยอีเมล → ลงทะเบียน (ชื่อ-นามสกุล, **รหัสพนักงาน**, สาขา) → รออนุมัติ → HR อนุมัติ → เริ่มเรียน
  - สมัครด้วย Google ก็ต้องกรอกรหัสพนักงานและสาขาเหมือนกัน และต้องรอ HR อนุมัติเหมือนกัน
  - **ส่งลิงก์ทาง LINE:** เบราว์เซอร์ในแอป LINE และ Facebook ไม่ยอมให้เข้าสู่ระบบด้วย Google ให้บอกพนักงานเปิดลิงก์ใน Chrome หรือ Safari (หน้าเว็บจะขึ้นคำแนะนำนี้ให้เอง) หรือใช้อีเมลและรหัสผ่านแทน
- **รหัสพนักงาน:** พนักงานต้องกรอกตอนลงทะเบียน ระบบเก็บเป็นตัวพิมพ์ใหญ่ไม่มีช่องว่าง (`da 104` → `DA104`)
  - HR ค้นหาด้วยรหัสได้ทั้งหน้าภาพรวมคะแนนและหน้าจัดการผู้ใช้ และรหัสอยู่คอลัมน์แรกของไฟล์ CSV
  - ถ้ามีสองบัญชีใช้รหัสเดียวกัน หน้าจัดการผู้ใช้จะขึ้นป้าย "รหัสซ้ำ" ให้ตรวจก่อนอนุมัติ
  - HR แก้รหัสให้ได้ที่ปุ่ม "แก้ไข"
- **เก็บประวัติให้องค์กร:** ข้อมูลอยู่ใน Firestore (`users`, `progress`, `signoffs`) ควรกด "ส่งออก CSV" ที่หน้าภาพรวมคะแนนเก็บไว้เป็นระยะ เช่น ทุกเดือน
- **คนที่ลาออก:** กด "ปิดการใช้งาน" แล้วประวัติการเรียนจะยังอยู่ครบ
- **ลบบัญชีถาวร:** ทำได้ที่ Console → Authentication → Users และลบเอกสาร `users/{uid}` กับ `progress/{uid}` ใน Firestore
- **ทำไมเข้าสู่ระบบด้วย Google หรืออีเมล ไม่ใช่รหัสพนักงาน:** ถ้าใช้รหัสพนักงาน คนที่ลืมรหัสผ่านจะรีเซ็ตเองไม่ได้ HR ต้องตั้งให้ผ่านเซิร์ฟเวอร์ (Cloud Functions) ซึ่งต้องใช้แพ็กเกจ Blaze ที่ผูกบัตร อีเมลจึงใช้เข้าสู่ระบบและรับลิงก์ตั้งรหัสใหม่ ส่วนรหัสพนักงานใช้ติดตามรายคน

## ความปลอดภัยของข้อมูล

- **`apiKey` ใน `firebase-config.js`:** เป็นค่าสาธารณะตามการออกแบบของ Firebase ตัวที่ป้องกันข้อมูลจริงคือ `firestore.rules` ซึ่งตรวจทุกคำขอที่ฝั่ง Google
- **บัญชีที่ยังรออนุมัติ:** มองไม่เห็นข้อมูลใครเลย
- **ผู้เรียน:** เห็นเฉพาะข้อมูลของตัวเอง
- **HR / หัวหน้า:** เห็นคะแนนของทุกคน
- **อีเมลผู้ดูแลระบบ:** ไม่อยู่ในไฟล์ที่ส่งไปยังเบราว์เซอร์ หน้าเว็บมีแค่ค่า SHA-256 ของอีเมล ส่วนรายชื่อจริงอยู่ใน `firestore.rules` ซึ่งเบราว์เซอร์อ่านไม่ได้
- **เนื้อหาบทเรียน (`course.js`):** ใครรู้ที่อยู่เว็บก็ดาวน์โหลดได้แม้ไม่ได้เข้าสู่ระบบ จึง **ห้ามใส่ราคาของซัพพลายเออร์หรือข้อมูลลับ** ลงในเนื้อหา
- **การค้นหา:** หน้าเว็บตั้ง `noindex` ไว้ Google จึงไม่นำไปแสดงในผลค้นหา
- **ค่าใช้จ่าย:** แพ็กเกจ Spark ไม่มีการเรียกเก็บเงิน ถ้าใช้เกินโควตาฟรี ระบบจะหยุดชั่วคราวจนถึงวันถัดไป ไม่มีบิล
  - Firestore อ่านได้ 50,000 ครั้งต่อวัน และเขียนได้ 20,000 ครั้งต่อวัน
  - Hosting ส่งข้อมูลได้ 360 MB ต่อวัน
  - ปริมาณนี้เพียงพอสำหรับพนักงานของคลินิก
- **ที่ตั้งฐานข้อมูล:** `asia-southeast1` (สิงคโปร์) ใกล้ไทยที่สุด ตั้งไว้ใน `firebase.json` ที่ `scripts/build_web.py` สร้าง ที่ตั้งเปลี่ยนภายหลังไม่ได้ ถ้าจะย้ายต้องลบฐานข้อมูลแล้วสร้างใหม่ ข้อมูลเดิมจะหายทั้งหมด
- **เสริมความปลอดภัยได้ถ้าต้องการ:**
  - จำกัด API key ให้ใช้ได้เฉพาะโดเมนของเว็บ ที่ Google Cloud Console → APIs & Services → Credentials → HTTP referrers โดยใส่ `smilegallerytraining.web.app/*`, `smilegallerytraining.firebaseapp.com/*` และ `localhost`
  - เปิด App Check
